# AiScript / Misskey Play を書くときの Tips

AI がコードを書くときに間違えやすい点を、AiScript 1.2.1 で実際に確かめてまとめたものです。
文法そのものは [aiscript/syntax.md](aiscript/syntax.md)、Play の関数は [play-api.md](play-api.md) を見てください。

## まず確認すること

- **1 行目**に `/// @ 1.2.1` を書く。コメントや空行より前に置くこと。書かないか、2 行目以降にあると、Misskey Play は 0.19.0 の処理系で実行する（書き方が違うので、多くのコードがエラーになる）。`/// @ 0.x.x` と書いた場合も 0.19.0 になる。この playground も同じ動きをする
- 文字列の連結に `+` は使えない。`"a" + "b"` は `Expect number, but got str.` になる。テンプレート文字列 `` `{a}{b}` `` か `[a, b].join()` を使う
- `??`（null 合体）と `?.`（オプショナルチェーン）はない。構文エラーになる。`if x == null "既定値" else x` と書く
- `if` は式なので値を返す。`else` がないと、条件が false のとき `null` を返す
- 負の数の書き方に注意する。`if c -1 else 1` は条件が `c - 1` と解釈され、構文エラーになる（条件を括弧で囲んでも同じ）。`if c (-1) else 1` か `if c { -1 } else 1` と書く。配列の `[x -1]` はエラーにならず `[x - 1]` の 1 要素になるので、`[x, -1]` とカンマで区切る
- `if`・`for`・`each`・`while` の直後と、ブロックの `{` の直前には空白が必要。`if(x)` や `for 5{` は構文エラーになる
- `return` は関数の中でしか書けない。トップレベルで処理を打ち切りたいときは、全体を関数にするか `Core:abort` を使う
- オブジェクトと配列の要素は `,` でも改行でも区切れる
- `==` はオブジェクトや配列を中身ではなく参照で比べる。`{a:1} == {a:1}` は `false` になる
- 配列の範囲外を読むとエラーになる（`Index out of range`）。オブジェクトにないキーを読むと `null` が返る
- `for let i = 1, 10` は「1 から 10 回」ループする（i は 1〜10）。「1 から 10 まで」ではない点に注意する
- 関数の中から外側の `var` に代入できる。`let` で宣言した変数には代入できない
- 文字列の n 文字目は `s.pick(n)`、長さは `s.len`、数値への変換は `s.to_num()`（変換できなければ `null`）
- 改行文字は `Str:lf`。テンプレート文字列の中で改行してもよい
- **文字列のエスケープシーケンスはない**。`"a\nb"` は改行にならず `anb` になる（`\` は次の 1 文字をそのまま入れるだけ）。改行は `Str:lf` かテンプレート文字列の中の改行で書く
- **予約語が多い**。`fn`・`out`・`in`・`is`・`as`・`do`・`use`・`new`・`this`・`meta`・`hash`・`table`・`class`・`enum`・`try`・`when`・`while`・`yield`・`ref` なども、変数名や関数名に使うと構文エラーになる（一覧は [aiscript/keywords.md](aiscript/keywords.md)）。オブジェクトのキーには使えるが、`obj.default` のような書き方では読めないので `obj["default"]` と書く
- `&&` と `||` は、左だけで結果が決まれば右を評価しない（短絡評価）。`x != null && x.len > 0` のように、null かもしれない値を先に調べてよい
- **配列の `map` と `flat_map` は、コールバックを並行して呼ぶ**（AiScript 本体の実装が `Promise.all`）。コールバックの中で外の変数を読んで書き換えると、ずれる。たとえば `count[k] = if count[k] == null 1 else count[k] + 1` で同じ種類を数えると、全部 1 になる。順番に数えたり、外の状態を変えたりするときは `each` を使う
- `Math:rnd(min, max)` と、`Math:gen_rng(シード)` が返す関数 `rng(min, max)` は、**min 以上 max 以下**の整数を返す（max も出る）。`rng(0, 1)` は 0 か 1。五分五分にしたいなら `rng(0, 1) == 1` でよい
- 型を調べるのは `Core:type(v)`。返り値は `"str"`, `"num"`, `"bool"`, `"null"`, `"arr"`, `"obj"`, `"fn"`, `"error"` のいずれか

## 宣言の順番（AiScript 1.2.1 で確認済み）

- トップレベルで、**後ろに書いた `@関数` を呼ぶとエラー**になる（`No such variable`）。関数の宣言は先に読み込まれない
- 関数の中から、後ろに書いた `@関数` や `let` を使うのはよい。呼ばれる時点で宣言済みなら動く
- **名前空間 `:: 名前 { ... }` は、実行の前に読み込まれる**。いちばん下に書いても、上から `名前:関数()` で呼べる。名前空間の中では、同じ名前空間の関数を `関数()` と短く呼べる。上で宣言した変数も読める
- 名前空間の中には `let` と `@関数` だけ置ける。`var` は置けない（状態は名前空間の外に置き、引数で渡す）
- この性質を使って、ゲームの中身を上、部品（`:: Lib`）とテストを下に置く形がおすすめ（[minigame.md](minigame.md) を参照）

## 書いても大丈夫なこと（AiScript 1.2.1 で確認済み）

心配になりがちだが、問題なく動く書き方です。

- 関数の中から、後ろで宣言した `let` 変数を使ってよい。呼ばれる時点で宣言済みなら動く（場面の定義を最後にまとめて書く、など）
- 関数の最後に `{ text: "x", value: id }` のようなオブジェクトを書くと、ブロックではなくオブジェクトとして返る
- 添字を使った複合代入ができる。`o[k] += 2`、`arr[0] += 5`
- オブジェクトの値に `if` 式を書ける。`{ v: if t { "yes" } else { "no" } }`
- テンプレート文字列の `{ }` の中に `if` を書き、その中にさらにテンプレート文字列を入れられる
- `Mk:confirm`・`Mk:dialog`・`readline` は `onClick` などのコールバックの中でも使え、答えるまで待つ

## MFM でよく使う書き方

`Ui:C:mfm` の文字列では、次のような MFM が使える。

- 色: `$[fg.color=e0533d 赤い文字]`、`$[bg.color=ffd700 背景]`（色は 16 進数で、`#` を付けない）
- 太字・打ち消し・小さい文字: `**太字**`、`~~打ち消し~~`、`<small>小さく</small>`
- 中央寄せ: `<center>中央</center>`
- 大きさと動き: `$[x2 大きく]`、`$[tada 🎉]`、`$[jelly ...]`、`$[shake ...]`
- 押せる箇所: `$[clickable.ev=名前 文字]`（`onClickEv` で受け取る）
- 枠: `$[border.color=fff,width=2,radius=6 中身]`（`bg`・`fg` と組み合わせると、枠付きのウィンドウになる）

### MFM の間違えやすい点（Misskey 本体のソースで確認）

- **`x2`〜`x4` と `tada` は場所を取る**。どれも文字の大きさを変える（`tada` は 150%）ので、絵文字を並べた盤面に使うと、その段だけ幅が広がってずれる。見た目だけ大きくしたいなら `$[scale.x=2,y=2 …]`（最大 5）を使う
- **`position` は見た目だけを動かす**。元の場所は空いたまま残る。値に上限はない。重ねて表示する方法は [mfm-layout.md](mfm-layout.md) を参照
- **見えない詰め物は `$[scale.x=0,y=0 ⬛]`**。幅を保ったまま見えなくなる
- **色は 3・4・6 桁の 16 進数**。4 桁なら最後の桁が透明度（`0000` は透明）。8 桁などそれ以外は赤（`f00`）になる
- **`<center>` は行の頭でだけ効く**。中身が空の `<center></center>` は、タグが文字のまま出る
- **入れ子は 20 段まで**。`$[ ]` に加えて `<center>` や `**` も数える
- **見る人の設定で効かない関数がある**。`position`・`scale`・`x2`〜`x4` は「高度なMFMを有効にする」、アニメーションは「動きのあるMFMを有効にする」がオフだと効かない
- **アニメーションは止まらない**。1 回だけ見せたい演出は、その場面のあいだだけ文字に入れる

## 絵文字と MFM が効く場所

- **MFM が効くのは `Ui:C:mfm` だけ**。`Ui:C:text` と、ボタン（`button`・`buttons`・`postFormButton`）の文字は平文で、Misskey 本体もそのまま表示する。`:カスタム絵文字:` や `$[...]`・`**太字**` は、文字のまま出る。キャラクターの名前やアイコンにカスタム絵文字を使うかもしれないなら、それを表示する部品は `Ui:C:mfm` にする
- **絵文字の見た目が場所で変わる**。Misskey の既定では、MFM の中の絵文字は Twemoji の画像になり、ボタンや `Ui:C:text` の絵文字は OS の絵文字（iPhone なら Apple、Windows なら Segoe）になる。見た目をそろえたいなら、ボタンに絵文字を入れない
- **カスタム絵文字は大きい**。MFM の中では、カスタム絵文字は高さ 2em、普通の絵文字（Twemoji）は高さ 1.25em で描かれる（Misskey 本体のソースで確認）。絵文字を並べた盤面にカスタム絵文字を混ぜると、そのマスだけ 1.6 倍になって列がずれる。盤面には普通の絵文字を使い、カスタム絵文字は文章やステータスに使う
- この playground の MFM も、Misskey の既定と同じく Twemoji で描く（⚙ 設定で OS の絵文字に切り替えられる）。静的チェックは、平文の部品に `:名前:` や `$[` を書くと注意を出す（`plain-text-mfm`）

## Ui:C:* の部品

- 部品は `Ui:render([...])` か、表示中の container・folder の `children` に入れたときだけ表示される。作っただけでは表示されない
- 表示を変えるときは、部品を作り直すより `部品.update({ ... })` を使う。渡したプロパティだけが変わり、ほかは元の値のまま残る
- **省略できるプロパティに `null` を渡すとエラーになる**。たとえば `color: null` は `Expect string, but got null.` になる。値を消したいときはキー自体を書かないか、`"inherit"` のような有効な値を渡す
- `hidden` が効くのは `Ui:C:container` だけ。ほかの部品を隠したいときは container で包む
- **`fgColor` を付けた container の中にボタンを置かない**。ボタンの文字色は container の `fgColor` を引き継ぐが、ボタンの背景はテーマの色（ライトテーマでは白に近い）のまま変わらない。たとえば白い文字の container に入れたボタンは、ライトテーマで文字が読めなくなる。色付きの箱には文章だけを入れ、ボタンは箱の外に置く（Misskey 本体の MkButton の作りを確認済み）
- `Ui:C:*` の第2引数に id を渡すと、`Ui:get(id)` で取り出せる。省略すると自動で id が付く
- `Ui:render` は画面全体を差し替える。部分的に変えたいなら、その部分を container にして `children` を `update` する
- `textInput` と `textarea` の `onInput` は1文字入力するたびに呼ばれる。確定時だけ処理したいならボタンを別に置く
- `numberInput` の `onInput` は数値（num）を受け取る。`select` の `onChange` は選ばれた要素の `value`（省略時は `text`）を受け取る
- `select` の `default` には `items` の `value` を書く
- `buttons` の各要素では `text` と `onClick` が必須
- `postFormButton` と `postForm` の `form.text` は必須
- MFM の中で押せる箇所を作るには `$[clickable.ev=名前 文字]` と書き、`Ui:C:mfm` の `onClickEv: @(ev) { ... }` で受け取る
- コールバック（`onClick` など）の中で起きたエラーは、スクリプト全体を止めずにエラーとして表示される

## Mk:* の関数

- `Mk:api` は失敗しても例外を投げず、error 型の値を返す。`if Core:type(res) == "error" { ... }` で判定し、`res.info` で中身を見る
- 本番の Play では `Mk:api` はトークンなしで呼ばれるため、`i` や `notes/create` のようにログインが必要な API は失敗する。投稿させたいときは `Ui:C:postFormButton` を使う
- `Mk:dialog`・`Mk:confirm`・`readline` は、ユーザーが閉じるまで次の行に進まない。`Mk:toast` は待たない
- `readline` でキャンセルされると空文字列 `""` が返る
- `Mk:save` / `Mk:load` は Play ごとに保存先が分かれる。保存できるのは JSON にできる値だけで、関数は保存できない
- `<:` と `print` の出力は、本番の Play では画面のどこにも表示されない（スクラッチパッドでは表示される）。ユーザーに見せたい値は `Ui:C:text` などで表示する
- 本番の Play では、実行時エラーはダイアログで表示される
- 日替わりの結果のように「同じ条件なら同じ値」にしたい乱数は `Math:gen_rng(シード)` で作る。`Math:rnd()` は毎回違う値を返す

## この playground と本番の違い

- `Mk:api` は既定で同梱のモックサーバーに送る。モックは `settings.dummyUser` のユーザーとしてログインしている扱いなので、本番の Play と違い `i` や `notes/create` も成功する。対応エンドポイントは `src/mock/api.ts` の `handlers` にある
- ⚙ 設定で実サーバーに切り替え、トークンを入れると、トークン付きで呼ぶ（スクラッチパッドと同じ動き）
- `<:` の出力はコンソールに出る。本番の Play では出ない
- playground にだけ、定数 `PLAYGROUND` とテスト用の関数 `Test:check` などがある。`if exists PLAYGROUND { ... }` の中でだけ使えば、Misskey に貼っても害がない（[testing.md](testing.md)）
- バージョン表記がないときに 0.19.0 で実行するのは、本番の Play と同じ。スクラッチパッドは表記に関係なく 1.x で実行するので、そこだけ違う
- `THIS_ID` は `"playground"`、`THIS_URL` はこのページの URL になる
- MFM の表示は mfm-renderer を使っているので、Misskey 本体と見た目が少し違う。`$[unixtime]` などの未対応の関数は `$[名前 ...]` のまま表示する
